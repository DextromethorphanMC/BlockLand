# BlockLand

Minecraft 1.21.8 / Forge 58.1.26 小游戏服务器：CS2 风格游戏大厅 + 空岛战争 + 快速PVP（含 ClassPVP），配置由 Java 后端 + React 后台管理。

```
BlockLand/
├─ mod/              Forge 模组（单一模组 blockland，客户端与服务端共用一个 jar）
└─ server/
   ├─ backend/       Spring Boot 3.5 (Java 21) REST API，JSON 文件存储
   └─ web/           React 19 + Vite 管理后台
```

## 架构

```
React 后台 ──/api/admin (Bearer admin-token)──▶ Spring Boot 后端 ◀──/api/server (X-Server-Token)── Forge 服务器
                                                  data/*.json + data/maps/*          (每 30 秒按 ETag 拉取配置)
Forge 服务器 ◀──SimpleChannel──▶ 客户端大厅界面
```

低耦合要点：

| 层 | 抽象 | 说明 |
|---|---|---|
| 模组 · 游戏类型 | `server/game/GameType` + `GameTypeRegistry` | 大厅、匹配、对局管理只认识接口；新增小游戏只需实现并注册一个 `GameType` |
| 模组 · 团队竞技场 | `games/common/TeamArenaGame` | 地图粘贴、玻璃笼倒计时、淘汰、胜负/限时、计分板队伍等通用流程；`games/skywars`、`games/fastpvp` 只通过钩子添加各自逻辑 |
| 模组 · 开局装备 | `server/kit/KitService` + `KitLayoutStore` | 任何游戏类型都可使用的开局装备。布局由客户端保存，排队时随请求发送；服务端只校验它是预设的重新排列（物品相同、盔甲不动），发放的永远是服务端预设的物品 |
| 玩家 / 权益 | 后端 `player/PlayerService`，模组 `server/player/PlayerProfiles` | 在线时长（服务器每 15 秒上报）、封禁、禁言、权益。商店只「授予权益」，匹配只「询问权益」，两者互不依赖 |
| 商店 / 支付 | 后端 `shop/ShopService` + `payment/PaymentProvider`，模组 `server/shop/ShopRelay` | 支付走 `PaymentProvider` 接口（当前 `MockPaymentProvider` 直接成功），接入真实支付只需新增实现；客户端不直接访问后端，商品由游戏服务器转发 |
| 图片 / 封面 | 后端 `media/MediaService`，模组 `server/media/MediaRelay` + 客户端 `ClientMedia` | 商品图片、模式封面、分组封面共用一套「命名空间 + id + 版本」存储与转发；业务模块只保存版本号，客户端按版本缓存纹理 |
| 模式分组 | 后端 `modegroup/*`，模组 `ModeGroupDef` / `LobbyGroupEntry` | 分组只引用模式 id，不改变模式本身；删除模式时自动从分组中移除；在后台「小游戏管理」中维护 |
| 组队 | 模组 `server/party/PartyService` + `PartyPackets` | 组队只管成员与邀请（按玩家 id，经 `PlayerDirectory` 找人、发提示），邀请前查询被邀请者的隐私设置；通过监听器通知变化；匹配只接收「必须同队的一组玩家」，对局只接收 `MatchRoster`（已分好的队伍 + 想要的地图），三者互不依赖 |
| 大厅 / 会话 | 模组 `server/session/*`（`PlayerSessions`、`LobbyGate`、`PlayerDirectory`）、`server/game/PlayerTransit` | **大厅就是连接的配置阶段（configuration phase）**：登录时加入的 `LobbyGate` 任务不会自己结束，玩家停在配置阶段，客户端与服务端都不加载任何世界；匹配到的对局准备好地图后通过 `PlayerTransit.bring` 让玩家进入世界（首次结束 `LobbyGate`，之后 `returnToWorld()`），结束后 `switchToConfig()` 送回大厅。Forge 的登录/登出事件因此只表示「进入/离开世界」，加入/离开服务器由 `PlayerSessions.Listener` 通知；大厅服务（组队、匹配、个人资料、商店、图片）只按玩家 id 工作，配置阶段的包由 `BLNetwork.anyToServer/anyToClient` 注册、按连接识别发送者 |
| 工匠 | 通用 `craft/*`（`Build`、`Craftable`、`CraftCatalog`、`Spray` + `SprayCatalog`），数据 `data/blockland/craft/attachments.json` + `sprays.json` + 各武器 `slots`，服务端 `server/craft/CraftService`，客户端 `client/craft/*`（`SprayEditor`）与 `client/spray/*` | 枪械与刀具共用：武器声明自己的槽位（挂点节点、默认、可选项、装上后隐藏的节点），配件只定义一次、任何武器都能用（瞄准镜、激光、枪管、枪托、挂件）；**喷漆**是改装方案的一部分：每处喷漆只存「喷漆 id + 哪一侧 + 侧视图中的 (u, v) + 尺寸 + 角度」，服务端不需要模型就能校验（id 存在且适用于该武器、坐标在 0..1、尺寸/角度在 `sprays.json` 的范围内、数量不超过上限），客户端按武器根节点的静止姿态把它投影到表面（`VIEWMODEL_SPEC.md` §29）；改装方案按玩家保存在**服务端**（后端玩家数据 `builds`，后端再检查一次格式），服务端校验每一项后保存，发放开局装备时自动套用；客户端只负责编辑与显示 |
| 设置 | 客户端 `client/settings/*`，准心 / 命中标记 `client/hud/Crosshair` + `HitMarker` | 语言与视角灵敏度是原版选项；瞄准灵敏度倍率、准心与命中标记样式只影响本机表现，保存在客户端（`config/blockland-settings.json`）；隐私（是否允许被邀请组队）保存在后端玩家数据，由服务端在邀请时执行 |
| 公告 | 后端 `announcement/*`（随 `/bootstrap` 同步），模组 `LobbyService` 转发，客户端 `ClientAnnouncements` + `client/screen/lobby/Announcement*` | 后台发布/编辑/删除；每名玩家的已读状态保存在后端（跟随账号），客户端标记已读后立即更新本地并通知服务器 |
| 枪械 · 数据 | `data/blockland/guns/guns.json` + `gun/GunCatalog` / `GunStats` | 弹药、弹匣、槽位、皮肤、枪械全部是数据（通用配件在 `craft/attachments.json`）；伤害/散布/后坐力/换弹时间/射程等有效数值（含配件的倍率）只在 `GunStats` 计算，客户端与服务端共用同一份 |
| 枪械 · 服务端 | `server/gun/GunService` | 唯一权威：校验每一枪（当前栏位、射速、余弹），用与客户端相同的散布种子做射线判定、爆头与距离衰减（消音器等配件的射程/伤害倍率），计时换弹并扣除背包弹药；双持武器的齐射（`shots` 2，只有 `dual.volley` 的武器可用，按 `volleyCost` 扣射速额度）与左右手（`hand`）都在这里校验；管式弹仓逐发装填由服务端按发计时、每发扣一颗弹药，开火可打断 |
| 枪械 · 客户端 | `client/gun/*`（输入、预测、HUD）、`client/gltf/*`（GLB 解析与动画采样）、`client/render/*`（GPU 渲染） | 客户端只做表现与预测；美术资源只通过 `tools/assets/VIEWMODEL_SPEC.md` 约定的节点名/动画名/材质名接入，换成美术制作的 GLB 无需改代码 |
| 第一人称 · 共用 | `client/viewmodel/*`（`ViewmodelRig`、`ViewmodelMotion`、`ViewmodelRenderer`） | 所有武器共用的部分：GLB 动画层（待机 / 单次动作 / 交叉淡化 / 疾跑循环）、相机节点、玩家皮肤手臂、程序化运动与独立视场角渲染；枪械（瞄准、后坐力、套筒、枪口火焰、激光）与刀具（命中回弹、镜头冲击）只在各自的视图模型里叠加 |
| 渲染 · 材质与皮肤 | `client/render/*`（`Textures` + `Mipmaps` 纹理组、`GpuModel` 逐材质解析、`DrawList`、`core/gun` PBR 着色器），`craft/SkinLibrary` + `data/blockland/craft/skins.json` | 材质是「数据 + 约定」：GLB 材质的 `extras` 指向 LabPBR 纹理组（颜色 / `_n` 法线 + AO / `_s` 光滑度、F0、自发光）并标明区域（枪身、枪管、弹匣、枪托、握把、护木、瞄具…）；皮肤按区域替换纹理组并可加着色器特效（`iridescent` 薄膜干涉、`flow` 流光、`galaxy` 星空、`circuit` 霓虹回路——在武器静止姿态空间里铺开，配件按挂点位置接续，图案跨枪身与配件无缝），共享皮肤按 `for` 自动加入每把对应武器，客户端与服务端读同一份数据、校验不变（`VIEWMODEL_SPEC.md` §20–§21）。**特殊皮肤**（§30）再多两样数据：`model`（遵守同一节点约定的另一个 GLB）与 `fx`（枪口火焰颜色/贴图/大小、曳光颜色/粗细、枪声）；服务端只用其中的枪声，其他玩家的客户端从射手手中物品读出皮肤来显示火焰与曳光 |
| 光影兼容 | `client/render/ShaderPacks`（反射读取 OptiFine 状态）、`client/render/VanillaDraws` | 检测到 OptiFine 光影包时，第一人称武器改走原版实体渲染类型（由光影包着色，并读取纹理组同名的 `_n` / `_s`），光影阴影阶段不绘制，瞄准镜退回整屏放大；没有 OptiFine 时这些代码完全不参与 |
| 光学瞄具 | 客户端 `client/scope/*`：门面 `Optics`（所有瞄具：机械、红点/全息 `ReflexSights`、倍镜 `Scopes`），倍镜的画中画 `ScopePicture`、目镜 `ScopeEyepiece`、瞄准聚焦 `AimFocus`（所有瞄具）、可变倍率 `ScopeZoom`、呼吸与屏息 `ScopeSteady`、他人镜片反光 `ScopeGlints`、纯数学 `ScopeOptics`；服务端 `server/gun/GunService`（开镜计时）；数据为 `attachments.json` 中配件的 `scope` / `reflex` 对象 | 枪械模块只通过 `SightPose`（瞄具节点在本帧的位置）与门面交互，光学模块不认识枪。镜内画面是独立的第二次世界渲染（同一帧、同一相机、窄视场、按目镜像素决定分辨率，只在开镜时），与主画面隔离（裁剪视锥不绘制调试平面、独立的雾 uniform、不画名牌）；目镜着色器负责出瞳阴影、视差、分划辉光、色散、太阳眩光与鬼影、镜片污渍和按真实天空着色的反光。开镜后子弹沿本帧画出的瞄准线射出（准星即落点）；开镜状态由客户端上报（`C2SAim`），**服务端计时**，射击声称的瞄准程度不能超过开镜时间允许的值，并转发给附近玩家显示狙击镜反光（`S2CAim`）。倍率、晃动、屏息、虚化只影响本机表现。栓动节奏在 `client/gun/BoltCycle`（`VIEWMODEL_SPEC.md` §22–§23） |
| 武器输入 | `client/input/WeaponInput` | 左/右键的真实按下沿与共用的检视键（`I`）；枪械与刀具各自订阅，只在自己的武器在手时响应 |
| 移动 · 滑铲 | 通用 `movement/*`（`SlideRules` 数据、`Slides` 两端视图）与 `combat/HitShapes`，服务端 `server/movement/SlideService`，客户端 `client/movement/*`（`ClientSlide` 预测与镜头、`SlidePose` 第三人称） | 是否允许是模式设置 `allowSlide`（类型可再收紧，如感染只允许人类）；客户端预测、服务端校验并下发姿态；枪械与刀具只通过 `Slides.eyePosition` / `HitShapes` 询问，不认识滑铲模块；武器的侧翻由共用的 `ViewmodelMotion.BodyMotion` 接入 |
| 刀具 · 数据 / 服务端 | `data/blockland/melee/knives.json` + `melee/*`，`server/melee/MeleeService` | 轻击 / 重击的伤害、距离、范围、出刀与命中时间、冷却、击退、背刺倍率、连击动画与切痕方向全部是数据；`MeleeTrace` 由服务端（伤害）与客户端（即时特效）共用。服务端唯一权威：校验栏位与冷却，在命中时刻重新判定并结算伤害，与枪械模块互不依赖（独立的 `MeleePacketListeners`） |
| 刀具 · 客户端 | `client/melee/*` | 输入（左键轻击可按住连斩、右键重击、检视）、连击交替、按键缓冲、命中时刻的本地特效与镜头冲击；共用 `client/hud/HitMarker` |
| 对局结算 | 模组 `server/game/MatchResult` + `MatchResultPublisher`，客户端 `client/result/*` | 游戏只用数据描述结果（胜负、原因、统计列、每名玩家一行）；发布器为每名玩家生成自己的结算面板（自己的胜负、高亮自己那一行）并下发，面板时长 = 结束阶段时长；按钮发 `C2SPostMatch`，服务端只在该玩家的对局处于结束阶段时接受，「再来一局」的模式取自服务端的对局记录、走与大厅相同的排队校验（队伍、装备布局） |
| 枪战感染 | 模组 `games/infection/*` + `data/blockland/infection/monsters.json` | 独立的游戏类型（不继承团队竞技场流程，只复用 `ArenaLoader` 载图与开局装备）；怪物的模型、血量、移速、技能全部是数据，技能按 `type` 由 `MonsterSkills` 实现（`effect` 自身效果、`projectile` 发射物）；左键伤害是模式设置、所有怪物一致；出生点角色读取地图的类型设置 `spawns`；怪物列表通过 `GameType.registryData()` 发布给后端；客户端只通过 `InfectionPackets` 收到要显示的内容，选择怪物与技能都由服务端校验 |
| 生物与效果 | 模组 `entity/*`（`SlimeLicker`、`SlimeShot`、`EffectPayload`）、`effect/*`（`BLEffects`、`ActionLocks`），客户端 `client/creature/*`、`client/effect/ClientActionLock` | 与游戏无关的内容：粘液舔舐者实体（改造的僵尸模型，供变身使用）、带效果的发射物、「粘液缠身」效果。`ActionLocks.isLocked` 是唯一的判断：枪械、刀具服务端拒绝被锁玩家的开火/攻击，原版攻击、使用物品、方块/实体交互同样取消；客户端据此即时屏蔽左右键并铺上粘液画面 |
| 玩家变身 | 模组 `server/morph/Morphs` + 客户端 `client/morph/ClientMorphs` | 与游戏无关：服务端只告诉客户端「把某玩家画成某种实体」；客户端用一个不入世界的代理实体按玩家的动作（走路、转头、攻击、蹲下、受伤）绘制原版模型，第一人称换成该实体的手臂 |
| 损伤贴图 | `client/decal/*` + `assets/blockland/decals.json` | 与武器无关：武器只调用 `Decals.onBlock` / `Decals.onEntity` 并传入数据里的贴图类型 id。每个贴图有自己的存在时间（类型时长 ± 随机）并在末尾淡出，每类有数量上限；方块贴图贴合并裁剪到被击中的面（同平面的相邻方块会延伸），方块变化时消失；身体贴图跟随人形模型的部位（头、躯干、四肢）。按贴图纹理一批一次绘制，带深度偏移不闪烁 |
| 中转位置 | 模组 `server/lobby/LobbyWorld` | 大厅里没有世界；玩家离开世界前被移到空的 `blockland:lobby` 维度（下次进入世界先在这里加载，再被对局移走），管理员「进入世界」也落在这里；主世界不保留出生点区块 |
| 模组 · 动画 | `anim/*`（纯 Java，无 Minecraft 依赖） | GSAP 风格：`Tween`、`Timeline`（位置参数 `<` `>` `+=` 标签）、`Ease`（含 `parse("back.out(1.7)")`、cubic-bezier）、`Stagger`、`Spring`、OKLab 颜色插值；UI 只通过 `AnimValue` / `Spring` 读值 |
| 模组 · 大厅界面 | `client/screen/LobbyScreen` + `client/screen/lobby/*` | 屏幕只负责布局与连线；`TopBar`、`ModeBrowser`、`MatchPanel`（含地图选择）、`CharacterStage`（无实体，直接用皮肤绘制玩家模型）、`PartyPanel`、`AnnouncementsPanel` / `AnnouncementReminder` 各自持有动画状态，`client/ui/Draw` 提供光晕、渐变、封面裁切等绘制；配置阶段没有原版界面负责连接，大厅自己维持连接；界面文字全部走语言文件（`client/ui/Tr`） |
| 模组 · 界面字体 | `client/font/*`（`UiFont`、`FontFace`、`GlyphAtlas`、`TextLayout`），字体 `assets/blockland/fonts/`，工具 `tools/fonts/subset_fonts.py` | 模组所有界面与 HUD 的文字都用自己的字体渲染：FreeType 读取 TTF/OTF，字形按需生成有向距离场（后台线程，每帧少量即时），用 `ui_text` 着色器经 GUI 渲染状态绘制，任意缩放都清晰；尺寸与原版文字一致（行高 9），支持组件样式与 § 代码、中英文断行（禁则）与省略号；字体缺的字符退回原版字体。字体为 **Noto Sans SC**（SIL OFL 1.1，可商用，许可证 `fonts/OFL.txt`）的子集；语言文件加字后运行 `python tools/fonts/subset_fonts.py --check` 检查覆盖 |
| 小游戏专属数据 | 地图 `settings` + 同步接口 `typeData` | 物资表、箱子坐标只属于空岛战争（后端 `gametype/skywars`、模组 `games/skywars`、前端 `gametypes/skywars`），其他小游戏完全不依赖 |

| 游戏类型注册表 | 后端 `registry/GameTypeRegistryData`；`POST /api/server/registry/game-types/{TYPE}`（游戏服务器）、`GET /api/admin/registry/game-types/{TYPE}`（后台） | 游戏服务器按类型发布自己提供的内容（任意 JSON，例如枪战感染的怪物列表），后端保存最后一次发布；类型定义（警告）与后台表单只从这里读取，不写死内容 |
| 后端 · 存储 | `storage/Repository<T>` | 当前为 JSON 文件实现，可替换为数据库 |
| 前端 · 游戏类型 | `src/gametypes/index.tsx` | 每种类型一个设置表单，可选地图编辑面板与俯视图标记（`gametypes/skywars` 箱子、`gametypes/infection` 角色出生点、`gametypes/fastpvp`），地图池选择共用 `gametypes/common/MapPoolField`；未知类型自动退化为 JSON 编辑 |

## 功能

- **游戏大厅**（进服后强制显示，对局结束后自动回到这里）：**大厅里不加载任何世界**——玩家停在连接的配置阶段，客户端没有世界、服务端没有玩家实体，直到匹配成功、地图准备好时才直接载入对局地图，对局结束再退回大厅。大厅界面不能关闭（没有世界可回），顶栏右侧有「设置」「退出服务器」（OP 另有「进入世界」，在世界中按 `M` 或 `/bl lobby` 回到大厅）。
  - 标签页：**开始游戏** / **工匠** / **公告**（显示未读数）/ **商店**（模拟支付）。
  - 开始游戏：左侧「选择游戏模式」先显示分组卡片（封面、标题、介绍、模式数）与未分组的模式，点开分组后只显示该组模式（「‹ 全部模式」或 `ESC` 返回）；中间为玩家人物模型（固定角度、呼吸浮动）；右下角为所选模式、**地图选择**与「开始匹配 / 取消匹配」。
  - **地图选择**：选中模式后可选「随机地图」或该模式地图池中的任一张（左右箭头切换，点名称打开列表，有封面时显示缩略图），每个模式分别记住；排队时随请求发送，服务端校验地图属于该模式。想要不同地图的玩家不会被匹配到一起，选随机的玩家可与任何人匹配；同一局里第一个指定地图的队伍决定地图。
  - **公告提醒**：右上角（组队栏下方）显示**未读**公告，最多同时两条，带发布时间与内容摘要，按发布时间从旧到新；点「已阅」后下一条才补上来，点卡片在「公告」页打开全文。「公告」页列出全部公告（置顶在前，其余从新到旧），打开即标记已读，可「全部标为已读」。已读状态保存在服务器（换电脑也保留）。
  - 全部动效使用模组自带动画系统：开场依次入场、卡片弹簧悬停/按压、分组切换滑动 + 交错入场、按钮颜色过渡与匹配中扫光、计时跳动。
- **设置**（大厅顶栏「设置」；对局中按 `O` 或在暂停菜单右上角点「BlockLand 设置」）：
  - 通用：界面语言 简体中文 / English（切换后重新加载资源，大厅与游戏内全部文字随之切换）。
  - 枪械：视角灵敏度、瞄准灵敏度倍率（开镜时生效）；**准心**（形状：十字 / 十字+中心点 / T 型 / 圆点 / 圆环，颜色、不透明度、线长、粗细、间距、描边、是否随扩散张开）；**命中标记**（形状：斜叉 / 十字 / 圆环，命中 / 爆头 / 击杀三种颜色、大小、粗细、持续时间）；**瞄准镜**（镜内画面质量 关 / 低 / 中 / 高、瞄准时聚焦、开镜时镜外变暗、瞄准镜灵敏度）。颜色可选预设或用 RGB 滑块自定义，右侧实时预览准心与轮流播放的命中标记。保存在本机。
  - 隐私：是否允许其他玩家邀请我组队（保存在服务器，关闭后邀请会被服务器拒绝）。
- **公告（后台）**：「公告」页可发布多条公告（标题、多行内容、置顶），编辑、删除；游戏服务器在下次同步（默认 30 秒内）后推送给大厅中的玩家。
- **小游戏管理**：添加模式（Title、游戏类型、介绍、封面（16:9，自动缩放到 512×288）、启用、可选存活时间），首次启动自动生成 **空岛战争 1v1 / 4v4** 与 **ClassPVP**（含示例封面）。
- **模式分组**（后台「小游戏管理」页内，模式按分组列出）：封面、Title、介绍、排序、启用以及有序的小游戏列表；编辑模式时可直接选择「所属分组」。示例分组「空岛战争」（1v1、4v4）、「PVP 竞技」（ClassPVP）与「枪战感染」。
- **组队**：大厅右上角显示队伍成员头像（★ 队长，颜色表示大厅 / 匹配中 / 对局中），点「+」输入玩家名称邀请（被邀请者在设置中关闭了组队邀请时会提示对方不接受）；被邀请者在大厅中看到邀请卡片（接受 / 拒绝，60 秒有效）。只有队长可以开始匹配，整队一起排队并分在同一队伍；队员可取消匹配；成员变化会自动取消当前匹配。队伍人数超过模式每队人数时无法匹配。上限由配置 `party.maxSize`（默认 4）决定。
- **无世界大厅**：大厅期间客户端不加载世界、服务端不创建玩家实体，主世界不加载区块；进入对局时客户端直接载入对局地图。
- **限时模式**：小游戏可设置「限时开放」截止时间，到期后自动关闭（正在排队的玩家会被移出队列，进行中的对局不受影响）。大厅中限时模式带金色边框与「限时 · 剩余 N 天」标签（最后两天闪烁），分组卡片显示「限时」，右下角详情显示截止时间。
- **转让队长**：队长把鼠标移到队员头像上，点左上角的 ★ 即可转让；正在进行的匹配不会被取消。
- **枪械系统**（**P9 手枪**、**P9A 冲锋手枪**、**USP 手枪**、**双持 USP**、**汤姆逊冲锋枪**、**AK-47 突击步枪**、**KS-3 霰弹枪**、**AWP 狙击步枪**）
  - 操作：左键射击，右键瞄准（ADS），`R` 换弹，`I` 检视，`G` 打开工匠，`B` 切换射击模式（均可在按键设置中修改）。
  - 射击模式：每把枪声明支持的模式（`guns.json` 的 `fireModes`，第一个为默认）。**P9 手枪**仅半自动（每按一次左键一发，按住挖方块也不会连发）；**P9A 冲锋手枪**默认全自动（约 1050 发/分），可按 `B` 切换为半自动。
  - 弹药：手枪 / 步枪 / 冲锋枪 / 霰弹枪 / 狙击枪弹药（物品，每种有自己的伤害、爆头倍率与适配弹匣）；弹匣：标准 / 扩容（适配枪械、容量、换弹与开镜速度）。换弹从背包扣除对应弹药，创造模式不消耗。
  - 每把枪有自己的名称、GLB 模型、皮肤、检视与换弹动画、射速、后坐力、腰射/瞄准精度、距离衰减；全部在 `guns.json` 中配置。
  - 爆头：命中头部（眼睛略下方以上）伤害乘以弹药的爆头倍率；命中/爆头/击杀有不同的命中标记与音效。
  - **工匠**（原「枪匠」，枪械与刀具共用）：大厅「工匠」页可改装任意武器，对局中手持枪械或刀具按 `G` 改装手上的武器；实时 3D 预览（拖动旋转、滚轮缩放），属性条显示改动带来的变化。
    - 枪械槽位：**瞄准镜**（机械瞄具 / 迷你红点 / 红点镜 / **二倍镜** / **狙击镜**）、**激光**（无 / 红色 / 绿色）、**枪管**（标准 / **消音器**：枪声变为消音枪声、几乎没有枪口火焰，射程与伤害略降）、**弹匣**（各枪专用）、**枪托**（无 / **战术枪托**：后坐力 -15%、开镜略慢 / **重型枪托**：后坐力 -25%、开镜明显变慢、腰射略散 / **钢丝枪托**：后坐力 -8%、几乎不影响开镜；P9、P9A、USP、汤姆逊、AK、KS-3 都有枪托槽，AK、汤姆逊、KS-3 装上后替换原枪托）、**挂件**（无 / **草方块挂件**，挂在武器上随动作摆动）、**喷漆**，以及外观三页：**迷彩**（普通皮肤：颜色与纹理组）、**特效皮肤**（动态着色器材质）、**特殊皮肤**（改变模型或射击效果）。
    - 配件是**通用**的：每个配件是独立的模型，挂在每把枪自己的挂点上，任何枪都能装任何瞄准镜、激光、消音器、枪托和挂件。
    - 刀具：迷彩（标准 / 暗影 / 猩红 / 深海 / 鎏金 / 大马士革 / 虎牙 / 渐变）、特效皮肤（星河 / 多普勒 / 霓虹回路）、喷漆与草方块挂件。
    - **喷漆**（枪械与刀具都有）：12 款原创喷漆（BlockLand 方块、骷髅、火焰、闪电、星星、爱心、GG、王冠、猫爪、靶心，传说 羽翼 / 龙纹），每把武器最多 4 处。在「喷漆」页选好喷漆和左侧 / 右侧，预览转到该侧，点击或拖动放到武器上，滚轮调大小、Shift+滚轮转角度；喷漆投影到武器表面（含装上的配件），跟随零件运动（贴在弹匣上的会随换弹离开）。
    - **特殊皮肤**（工匠的「特殊皮肤」页，标注「特殊皮肤」）：除材质外还会改变模型或射击效果——双持 USP「地狱犬」（独立模型、深红三叉枪口火焰、红色曳光、专属枪声）、KS-3「龙息」（熔岩材质、巨大橙色火焰与燃烧曳光）、汤姆逊「芝加哥」（鎏金金属、金色火焰与曳光）、AWP「雷霆」（淡蓝火焰与曳光）；其他玩家看到的火焰与曳光也随之改变。
    - **霓虹回路**（「特效皮肤」页，所有枪械与刀具）：动态着色器绘制的发光电路纹路，光脉冲沿纹路流向枪口、色相缓慢漂移，覆盖枪身每个区域与所有装上的配件，图案跨配件无缝相接。
    - **分区**：迷彩与特效皮肤按区域（枪身 / 枪管 / 弹匣 / 枪托 / 握把 / 护木 / 瞄具 / 激光 / 细节件，刀具为刀身 / 刀柄 / 五金）替换材质，同一款皮肤适用于每把枪和装上的配件。**特效皮肤**（动态着色器材质，工匠中标注「特效皮肤」）：枪械「极光」（随视角变色的钛金属薄膜涂层 + 流动的青色光纹）、「熔岩」（玄武岩与发光流动的熔岩裂纹）；刀具「星河」（刀身深处有视差的星空与星云）、「多普勒」（缓慢流转的彩色漩涡）。
    - 改装方案保存在**服务器**（跟随账号），服务端逐项校验（配件属于该槽位且该武器允许、迷彩/皮肤存在、喷漆合法），对局发放的武器自动套用。
  - **AWP**：狙击枪弹药、10 发弹匣，栓动（约 41 发/分）：每发之后瞄准镜放下、拉栓抛壳，按住右键时下一发上膛前自动重新开镜；40 格内打身体一枪倒地、爆头必杀，不开镜几乎打不准；默认装狙击镜（没有机械瞄具，瞄准镜槽不提供机械瞄具）；迷彩 标准 / 黑色 / 沙漠，特殊皮肤 雷霆。
  - **瞄准镜**：二倍镜（2×）与狙击镜（4× / 6× / 9× 可变，开镜后滚轮切换，画面平滑过渡）是通用配件，任何枪都能装。开镜时目镜里是**独立渲染的放大画面**，镜外视野保持正常（可选轻微变暗）；眼睛偏离光轴时画面收缩成暗环（举镜时小亮圆逐渐张开），晃动与后坐时镜筒边缘出现月牙阴影，分划随视差漂移并随枪身倾斜转动，发光分划带微弱辉光，边缘有色散、轻微桶形畸变与暗角，太阳靠近视野时出现眩光、鬼影并照亮镜片污渍（被方块挡住的太阳不会），镜片按玩家所处的天空与亮度反光（不再偏蓝）；狙击镜开镜后枪身随呼吸缓慢晃动，按住冲刺键屏息约 5 秒稳住准星（屏息耗尽后会抖动一会儿），目镜下方显示屏息条；开镜后**子弹沿瞄准线射出，分划中心就是落点**；开镜时鼠标灵敏度按当前倍率降低；举起狙击镜时，被瞄准方向上的其他玩家能看到镜片反光。开镜使用瞄准镜专用姿态：眼点沿瞄准线前移到较短的眼距，目镜按真实透视放大到约屏幕高度的 64%（狙击镜）/ 52%（二倍镜），眼罩就是镜框，镜筒全部藏在目镜后面；放大画面、分划和镜内阴影（视场光阑、出瞳）都在目镜玻璃里。镜内画面分辨率按目镜在屏幕上的像素决定，只在开镜时渲染。
  - **瞄准聚焦**：任何瞄具开镜时都以准星（倍镜为目镜）为中心保持一圈清晰，圆外从边缘到屏幕角落逐渐加深模糊（倍镜更强），武器本身不模糊；强度与半径可在配件数据 `focusBlur` / `focusRadius` 中调整，设置里可关闭。
  - **红点镜 / 全息瞄准镜**：分划由镜片着色器绘制为「无穷远」的光点——始终在瞄准线上、只在镜片范围内可见、没有视差（全息为环加点），正视镜片几乎不改变画面，靠近镜框处才有带镀膜色调的反光；激光照射点为小而圆的柔光点；镜筒内壁为哑光黑。只在开镜时渲染、分辨率可调；画中画关闭或使用 OptiFine 光影包时改为整屏放大 + 镜筒遮罩。F3 左侧显示镜内画面尺寸与耗时。
  - **材质（PBR）**：所有枪械、刀具与配件使用高分辨率 LabPBR 纹理组（颜色、法线、光滑度/粗糙度、环境光遮蔽、自发光）与烘焙的顶点环境光遮蔽，GGX 高光叠加原有的工作室灯光与 Minecraft 光照；同一套贴图在 OptiFine 光影包下由光影包读取。
  - **AK-47**：步枪弹药，标准 30 发 / 扩容 45 发弹匣，全自动（600 发/分）可切半自动，后坐力与惯性明显更重；迷彩 标准 / 黑色战术 / 沙漠 / 数码迷彩 / 鎏金。
  - 第一人称动画系统（枪械与刀具共用，以 COD 为标准）：完全不使用原版行走晃动（view bobbing）。
    - 状态：待机、行走、奔跑（武器放低斜持）、战术冲刺（开始疾跑的前几秒武器高举，冲刺时间用完转为奔跑，不疾跑时恢复）、举枪瞄准、开火、换弹、检视；这些动画按玩家速度与状态混合，单次动作用缓入缓出的权重叠加，任何切换都不会跳变。
    - 重量感：每把武器有自己的手感数据（`handling`：重量、晃动、步伐晃动、惯性、退出疾跑时间、战术冲刺时长、开镜倾斜），重的武器转身拖得更远、回正更慢；起步时武器落后、急停时向前甩；呼吸在疾跑后变深变快，再慢慢平复，开镜时几乎静止。
    - 开镜：举枪时武器先向内倾斜再回正，到位时有轻微的落定；开火：弹簧后坐力加方向性的镜头上扬（不再是随机抖动）；从疾跑中开火或开镜在退出疾跑时间内（手枪约 0.22 秒、AK 约 0.3 秒）完成；瞄准、射击或检视时不能疾跑（开始检视会立即停止疾跑）。
    - 手与手指：玩家皮肤的双手带手指关节，握枪、扣扳机、换弹按弹匣卡榫、拉枪机、检视时手指与零件配合；动画曲线支持 glTF CUBICSPLINE（缓入缓出、跟随、回弹）。
    - 比例与画面：手臂按真实比例收细（前臂从肘部约 5 cm 收到手腕约 4 cm，手掌与手指缩小约 12%），武器在腰射时只占画面右下方（16:9 下 P9 约 14%、AK 约 12% 的画面），准心周围不被遮挡；换弹与检视动作压低、推远，不再长时间挡住画面中央。
  - 表现：GLB 第一人称视图模型（玩家皮肤的手臂、相机空间动画、动画事件驱动音效），程序化瞄准对齐、弹簧后坐力与镜头震动；枪口火焰、抛壳（带物理与落地声）、曳光弹、弹孔碎屑、激光束与激光点、红点准镜分划。
  - GPU 优化：模型在加载时一次性上传到 GPU（单顶点缓冲 + 单索引缓冲，24 字节紧凑顶点），每帧只用一次 `writeTransforms` 写入所有节点的变换并在一个渲染通道内完成全部绘制；动画采样与矩阵计算无分配；第三人称/背包使用原版烘焙的低模（LOD），不对其他玩家做逐帧自定义绘制；枪匠预览只在构型或角度变化时重绘；视图模型使用独立的 54° 视场角（与射击游戏一致，枪械更大、畸变更小），P9 的腰射位置按该视场角调整，16:9 与 4:3 下整把枪（含扩容弹匣、激光、红点）都完整在画面内。
  - 实测（RTX 5090 Laptop、854×480、不限帧率）：完整改装的视图模型 28 次绘制、约 7.5k 三角形、CPU 0.05 ms/帧（F3 调试界面左侧显示 `[BlockLand] viewmodel` 实时数据）；同一画面手持枪械与空手的帧时间差约 0.13 ms，60 FPS 下约占 0.8% 帧预算。
  - **USP**：手枪弹药，12 / 18 发弹匣，半自动（约 380 发/分），单发伤害比 P9 高、精度高；迷彩 标准 / 沙色 / 银色套筒。
  - **双持 USP**：左右手各一把 USP，共用 24 / 36 发（两个弹匣）。左键左右交替射击，**右键双枪齐射**（一次两发、散布更大，射速额度按两发计）；不能开镜；两把枪一起换弹，每把打空时各自的套筒停在后方。第三人称两只手都拿着枪。服务端校验齐射与左右手。
  - **汤姆逊冲锋枪**：冲锋枪弹药，30 发直弹匣 / 50 发弹鼓（换弹与开镜更慢），全自动（720 发/分）可切半自动；枪口补偿器（装消音器时取下）、木质枪托与前握把。模型基于 CC-BY 模型改造（见 `tools/assets/CREDITS.md`）。
  - **KS-3 霰弹枪**：霰弹枪弹药（一发 8 颗弹丸），6 发 / 8 发加长管式弹仓，泵动（约 70 发/分，每发拉动护木抛壳）。**逐发装填**：每装一发计一发（客户端与服务端同步计时），装填中开火即可打断；空仓装填最后会拉一次护木上膛。模型基于 CC-BY 模型改造。
- **刀具系统**（**蝴蝶刀**、**匕首**），与枪械同一套技术栈（GLB 视图模型、玩家皮肤手臂、程序化运动、GPU 保留模式渲染），可在工匠中更换迷彩与皮肤、贴喷漆、挂上挂件
  - 操作：**左键轻击**（快速左右连斩，两段动画交替，按住持续挥砍），**右键重击**（蓄力后突刺），`I` 检视（蝴蝶刀花式翻转）。轻击 5 伤害、冷却 0.36 秒；重击 11 伤害、冷却 0.95 秒；从背后命中为**背刺**（轻击 ×1.5、重击 ×2，重击背刺可一击击杀满血玩家），命中标记为橙色并提示「背刺」。数值全部在 `knives.json` 配置。
  - **匕首**：双刃战术匕首，出刀更快（轻击 4.5 伤害、冷却 0.30 秒；重击是一记快速直刺，10 伤害、冷却 0.8 秒），重击背刺一击致命；检视时指尖转刀、翻成反握再翻回；迷彩 标准 / 暗影 / 大马士革 / 虎牙 / 鎏金，可挂草方块挂件、贴喷漆。
  - 攻击、检视时不能疾跑；切换武器会取消尚未命中的攻击；刀不能挖方块、不能触发原版近战与方块交互。
  - 命中：刀刃命中瞬间（动画中的接触点，与服务端判定时间一致）在客户端即时播放命中音效、血点/碎屑火花、武器回弹与镜头冲击，服务端重新判定后发回命中标记；其他玩家看到挥刀动作并看到命中的切痕。
- **滑铲**：在地面冲刺时按**下蹲**（或可在按键设置中绑定的「滑铲」键）滑出约 4 格（约 0.7 秒，冲刺越快滑得越远），可随视角微调方向，跳跃可带着速度跃出，撞墙或滑出边缘后结束，结束后有短暂冷却。每个模式可在后台单独开关（「允许滑铲」：快速PVP / 枪战感染默认开、空岛战争默认关；感染模式中怪物不能滑铲；不在对局中的世界由配置 `movement.slideOutsideMatches` 决定）。
  - 第一人称：镜头平滑降低到约 1 格高、轻微侧倾与视野拉伸，手中武器（枪与刀共用）侧翻压低；滑铲中可以开火、瞄准。第三人称：腿向前伸、上身后仰、头仍看向准星方向。
  - **判定框随姿态改变**：滑铲时碰撞箱为下蹲高度；子弹与刀的命中判定（服务端与客户端预测共用 `combat/HitShapes`）改为沿滑行方向的低矮身体框 + 位于臀部后上方的头部框（仍可爆头），射击/刀击的起点是滑铲时的低视角。
  - 客户端立即预测滑铲（手感无延迟），服务端校验模式是否允许、是否真的在地面冲刺、速度与冷却，通过后才给低姿态并同步给其他玩家；不合法的滑铲会被立即取消。数值在 `data/blockland/movement/slide.json`。
- **损伤贴图**：子弹击中方块留下**弹孔**（4 种随机样式、随机旋转、约 30 秒），刀击中墙壁留下**刀痕**（轻击为沿挥砍方向的划痕，重击为刺孔，约 22 秒），刀击中人物在被击中的身体部位留下**伤口**（约 10 秒，跟随人物转身与转头）。每个贴图有自己的存在时间（基础时长 ± 随机）并在最后几秒淡出；方块被破坏或改变时其上的贴图消失。外观、尺寸、时长与数量上限在资源包 `assets/blockland/decals.json` 中配置（F3+T 重新加载），F3 左侧显示当前贴图数量。
- **结算面板**：每局结束时服务端下发结算数据，屏幕上方弹出一张不占满屏幕的卡片（不暂停、背景游戏画面可见）：自己的「胜利 / 失败 / 平局」、模式与用时、获胜方与结束原因、所有玩家的统计表（自己那一行高亮，MVP 标星），以及两个按钮 **「再来一局」**（立即返回大厅并重新排队同一模式；队长会带上仍在结算的队员一起排队，队员则返回大厅等待队长）和 **「返回大厅 (N)」**（倒计时，归零时正好被送回大厅）。面板时长等于对局的结束阶段，回到大厅时面板已经关闭；按 Esc 可收起按钮，卡片留在屏幕上直到倒计时结束。空岛战争 / 快速PVP 显示击杀与存活状态，枪战感染显示胜局、击杀与感染数。
- **枪战感染**（独立的游戏类型 `INFECTION`，大厅中有自己的分组「枪战感染」，示例模式「枪战感染」）：可设置总人数 `players`、开局怪物方人数 `startMonsters`、游戏局数 `rounds`（多局制，哪方赢的局数多则获胜，胜负已定时提前结束，局间休息 `roundBreakSeconds` 秒）。每局所有人都以人类身份在人类出生点开始，拿开局装备（可在大厅「装备布局」中调整位置）；`infectionDelaySeconds` 秒后随机 `startMonsters` 名玩家变为**母体**（至少留一名人类）。人类无论以何种方式死亡都会被**感染**成怪物，原地变身并弹出**怪物选择面板**（显示模型、血量、技能与冷却，`selectSeconds`（默认 10）秒内未选择则自动选择默认怪物，选择期间无敌且不能攻击）；被击杀的怪物在 `monsterRespawnSeconds` 秒后于远离人类的怪物复活点复活。每局的存活时间（模式的「存活时间」，未设置时 180 秒）结束时还有人类存活则**人类赢下这一局**，人类全部被感染则**怪物赢下这一局**。结算时每名玩家按自己站在获胜方的局数（过半为胜）判定胜负。
  - 怪物：每种怪物有自己的模型（原版实体）、血量、移速、击退抗性与技能；**所有怪物的左键攻击伤害一致**（模式设置 `monsterDamage`，默认 6）。母体血量 ×`motherHealthMultiplier`（默认 2）。
  - **僵尸**：原版僵尸模型（双臂前伸、随玩家走动/转头/攻击），80 血，技能「狂暴」（按 `V`，可在按键设置中修改）：怒吼并获得 4 秒速度 III，冷却 18 秒。
  - **粘液舔舐者**：改造的僵尸模型（下颌脱落、长舌摆动、攻击时舌头甩出、背后搏动的粘液囊、佝偻姿态，专用贴图），60 血，移速略快，技能「粘液喷吐」：吐出一团粘液，命中的目标获得「粘液缠身」3 秒——这期间无法使用左键和右键（不能开火、开镜、挥刀、攻击、使用物品或与方块交互，服务端校验），屏幕上铺满一层缓缓下滴的绿色粘液，随效果结束逐渐消退。冷却 12 秒。
  - 第一人称显示怪物的手臂；右下角显示怪物、生命与技能冷却。怪物列表由游戏服务器发布给后端，后台表单只显示服务器实际提供的怪物。
  - 地图：每个出生点可设为「人类」「怪物」或「两者」（后台地图编辑器），人类在可用于人类的点开局，怪物在可用于怪物的点复活；没有设置时沿用 `teamSpawns`（第 1 组人类、第 2 组怪物）。示例地图 `infection_demo`。
- **枪战1v1**（FastPVP 示例模式，限时开放至 2026-11-30）：1v1，开局一把 P9 手枪 + 60 发手枪弹药 + 一把蝴蝶刀。
- **开局装备 / 装备布局**：支持开局装备的游戏类型（目前为快速PVP、枪战感染）在后台按背包格子配置装备；玩家在大厅选中模式后点「装备布局」可自行调整物品位置（盔甲固定），保存在**客户端**（`config/blockland-kit-layouts.json`），排队时发送给服务器校验；管理员修改装备后旧布局自动失效。
- **快速PVP（FASTPVP）**：自定义开局装备、是否允许破坏/放置方块（服务端以 Forge 破坏事件的 DENY 结果拒绝；两者都不允许时玩家处于冒险模式，客户端连挖掘都不会开始）、可选限时、每队人数 × 队伍数、自定义地图；淘汰后不掉落装备。示例模式 **ClassPVP**（1v1，铁套 + 铁剑，示例竞技场地图）。
- **用户（后台）**：玩家列表、在线状态、总在线时间、最后在线；封禁 / 禁言（原因 + 时长或永久，在线玩家 15 秒内被踢出或禁止聊天）；手动授予 / 收回权益。
- **商店（后台）**：商品包含名称、图片（自动转 PNG ≤256px，游戏内同步显示）、介绍、价格、分类、权益标识与有效期；订单列表。首个商品 **优先匹配排队**（¥9.90 / 30 天，授予 `PRIORITY_QUEUE`，重复购买顺延）。
- **优先匹配排队**：拥有 `PRIORITY_QUEUE` 权益的玩家在所有队列中排在最前面（同类按加入顺序）；大厅匹配面板显示「★ 优先匹配」，OP 可用 `/bl queue <模式ID>` 查看队列顺序。
- **空岛战争**
  - 导入地图：上传 `.nbt` / `.schem`，自动识别尺寸、所有箱子/木桶坐标，可选「出生点标记方块」自动生成出生岛（相邻标记归为同一队）。
  - 匹配人数：每队人数 × 每局队伍数（预设 1v1 / 2v2 / 4v4 / 8 人混战等）。
  - 物资：物资表中每个物品可设置数量范围与出现概率，支持 `/give` 组件语法（附魔等）；每箱最少/最多物品数；后台可「模拟开箱」。
  - 按坐标为每个箱子单独指定物资表（俯视图点选 + 批量设置），未指定的使用地图默认物资表；地图中未登记的箱子也会使用默认物资表。
  - 对局流程：加载并分批粘贴地图到独立虚空维度 `blockland:arena` → 玻璃笼倒计时 → 开战（队友无伤、虚空判定、击杀播报、可选箱子刷新）→ 最后存活队伍获胜 / 到达存活时间按存活人数判定 → 结算后返回大厅并清理场地。

## 运行

### 1. 后端 + 管理后台

```bash
cd server/web && npm install && npm run build
```

```bash
cd server/backend && mvn package
```

```bash
cd server/backend && java -jar target/blockland-backend-0.1.0.jar
```

打开 <http://localhost:8080>，使用 `application.yml` 中的 `blockland.admin-token` 登录。**上线前请修改 `admin-token` 与 `server-token`。** 数据保存在 `server/backend/data/`。

前端开发：后端运行时执行 `npm run dev`（<http://localhost:5173>，`/api` 自动代理到 8080）。

### 2. 模组

本机默认 `JAVA_HOME` 是 JDK 8，Gradle 9 需要 17+；`build.ps1` 会自动改用 JDK 26，并绕过 JDK 26 在本机 Windows 上的 NIO 管道问题（`Unable to establish loopback connection`）。编译用的 Java 21 工具链由 Gradle 自动下载。

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 build
```

产物：`mod/build/libs/blockland-0.1.0.jar`，服务端与客户端都需要安装。

开发测试（`mod/run-server` 已配置为离线模式 + 超平坦 + 仅本机 RCON）：

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 runServer
```

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 runClient -PjoinServer=localhost:25565 -PdevName=Steve
```

**服务器地址**：默认 `localhost:25565`（`server-ip` 为空 = 监听所有网卡，局域网内其他电脑用本机 IP:25565）。开发服务器是离线模式，同时开两个客户端只需名字不同，第二个客户端用独立的游戏目录：

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 runClient -PjoinServer=localhost:25565 -PdevName=Alex -PclientDir=run2
```

`build.ps1` 会把系统的 `HTTPS_PROXY`（如本机 Clash `127.0.0.1:7890`）转换为 Java 代理参数，否则 Mojang 资源下载会超时。

服务器配置 `config/blockland-common.toml`：

```toml
[backend]
url = "http://127.0.0.1:8080"
serverToken = "change-me-server"
syncIntervalSeconds = 30
```

开发服务器的 `ops.json` 已将开发客户端玩家 **Steve** 设为 4 级 OP（离线模式 UUID），用 `-PdevName=Steve` 启动客户端即可直接使用 OP 命令。

### 开发测试驱动

开发客户端可加 `-Pautomation=<目录>` 启动（例如 `.\build.ps1 runClient -PdevName=Steve -Pautomation=C:/tmp/auto`），
客户端会读取 `<目录>/<玩家名>.txt` 中的测试指令（按键、选栏位、执行命令、瞄准某玩家、截图等，见
`client/dev/DevAutomation.java`），结果追加到 `<目录>/<玩家名>.log`。不加该参数时完全不启用，不影响正常游戏。

### 武器美术资源

`tools/assets/` 下的程序化生成器（`python -I tools/assets/build_all.py`）生成 P9、USP、双持 USP、AK-47、AWP、蝴蝶刀与匕首的 GLB、通用配件（含二倍镜、狙击镜与分划贴图、三种枪托）、手臂、图标、低模、特效与损伤贴图、喷漆贴图、音效；汤姆逊、KS-3 与双持 USP 的「地狱犬」皮肤模型由转换脚本从 CC-BY-4.0 模型改造而来（作者与来源见 `tools/assets/CREDITS.md`，不附带原模型贴图；转换后的零件缓存在仓库里，没有原文件也能重新生成）。之后的武器各自用一组模块接入（`pbr_sets_*`、`pbr_models_*`、`build_*`、`check_*`，见各钩子元组），可以并行开发；`pbr_textures.py` 生成 LabPBR 纹理组，`pbr_apply.py` 把纹理组、区域与烘焙的顶点 AO 写进每个 GLB（`build_all.py` 会自动执行，单独重新生成 AWP / 瞄准镜后需再运行一次 `pbr_apply.py`），`pbr_check.py` 检查纹理组与皮肤数据，`check_glb.py` 还会把每个模型从 14 个方向不剔除背面地渲染一遍（`check_orient.py`），露出背面的零件（法线朝内、看进去像空心）、绕序不一致的面和不该透明的材质都会报错；
美术制作的模型只要遵守 `tools/assets/VIEWMODEL_SPEC.md`（节点名、相机空间、动画名与事件、材质名），放进资源包即可替换（F3+T 重新加载）。

### 游戏内命令

| 命令 | 说明 |
|---|---|
| `M` / `/bl lobby` | 在世界中（OP 进入世界后）返回大厅；大厅本身进服即显示 |
| `/bl join <模式ID>` | 用命令加入匹配队列（等同于大厅里的「开始匹配」，使用默认装备布局） |
| `/bl queue <模式ID>` (OP) | 查看队列顺序（★ = 优先匹配） |
| `/bl leave` | 离开对局（阵亡后观战时也可用）并返回大厅 |
| `/bl reload` (OP) | 立即同步后端配置 |
| `/bl status` / `/bl games` / `/bl stopall` (OP) | 状态、进行中对局、中止全部对局 |
| `/bl start <模式ID>` (OP) | 用队列中的玩家立即开局（可单人测试） |

## 坐标约定

地图中所有坐标都相对于结构/schematic 的最小角 `(0,0,0)`。出生点坐标是玩家**脚下所在的方块**；朝向 yaw 与 Minecraft 相同（0 = 南，90 = 西）。队伍按出生岛列表均匀分配，例如 8 个岛的 1v1 使用第 1 和第 5 个岛。
