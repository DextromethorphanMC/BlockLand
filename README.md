# BlockLand

Minecraft 1.21.8 / Forge 58.1.26 小游戏服务器：CS2 风格游戏大厅 + 空岛战争 + 快速PVP（含 ClassPVP），配置由 Java 后端 + React 后台管理。

```
BlockLand/
├─ mod/              Forge 模组（单一模组 blockland，客户端与服务端共用一个 jar）
└─ server/
   ├─ backend/       Spring Boot 3.5 (Java 21) REST API，JSON 文件存储
   └─ web/           React 19 + Vite 管理后台
```

## 架构

```
React 后台 ──/api/admin (Bearer admin-token)──▶ Spring Boot 后端 ◀──/api/server (X-Server-Token)── Forge 服务器
                                                  data/*.json + data/maps/*          (每 30 秒按 ETag 拉取配置)
Forge 服务器 ◀──SimpleChannel──▶ 客户端大厅界面
```

低耦合要点：

| 层 | 抽象 | 说明 |
|---|---|---|
| 模组 · 游戏类型 | `server/game/GameType` + `GameTypeRegistry` | 大厅、匹配、对局管理只认识接口；新增小游戏只需实现并注册一个 `GameType` |
| 模组 · 团队竞技场 | `games/common/TeamArenaGame` | 地图粘贴、玻璃笼倒计时、淘汰、胜负/限时、计分板队伍等通用流程；`games/skywars`、`games/fastpvp` 只通过钩子添加各自逻辑 |
| 模组 · 开局装备 | `server/kit/KitService` + `KitLayoutStore` | 任何游戏类型都可使用的开局装备。布局由客户端保存，排队时随请求发送；服务端只校验它是预设的重新排列（物品相同、盔甲不动），发放的永远是服务端预设的物品 |
| 玩家 / 权益 | 后端 `player/PlayerService`，模组 `server/player/PlayerProfiles` | 在线时长（服务器每 15 秒上报）、封禁、禁言、权益。商店只「授予权益」，匹配只「询问权益」，两者互不依赖 |
| 商店 / 支付 | 后端 `shop/ShopService` + `payment/PaymentProvider`，模组 `server/shop/ShopRelay` | 支付走 `PaymentProvider` 接口（当前 `MockPaymentProvider` 直接成功），接入真实支付只需新增实现；客户端不直接访问后端，商品由游戏服务器转发；权益标识是库存物品（如皮肤 `skin:usp_dual/cerberus`）的商品没有图片时，游戏内显示该物品自己的图标 |
| 图片 / 封面 | 后端 `media/MediaService`，模组 `server/media/MediaRelay` + 客户端 `ClientMedia` | 商品图片、模式封面、分组封面共用一套「命名空间 + id + 版本」存储与转发；业务模块只保存版本号，客户端按版本缓存纹理 |
| 模式分组 | 后端 `modegroup/*`，模组 `ModeGroupDef` / `LobbyGroupEntry` | 分组只引用模式 id，不改变模式本身；删除模式时自动从分组中移除；在后台「小游戏管理」中维护 |
| 组队 | 模组 `server/party/PartyService` + `PartyPackets` | 组队只管成员与邀请（按玩家 id，经 `PlayerDirectory` 找人、发提示），邀请前查询被邀请者的隐私设置；通过监听器通知变化；匹配只接收「必须同队的一组玩家」，对局只接收 `MatchRoster`（已分好的队伍 + 想要的地图），三者互不依赖 |
| 大厅 / 会话 | 模组 `server/session/*`（`PlayerSessions`、`LobbyGate`、`PlayerDirectory`）、`server/game/PlayerTransit` | **大厅就是连接的配置阶段（configuration phase）**：登录时加入的 `LobbyGate` 任务不会自己结束，玩家停在配置阶段，客户端与服务端都不加载任何世界；匹配到的对局准备好地图后通过 `PlayerTransit.bring` 让玩家进入世界（首次结束 `LobbyGate`，之后 `returnToWorld()`），结束后 `switchToConfig()` 送回大厅。Forge 的登录/登出事件因此只表示「进入/离开世界」，加入/离开服务器由 `PlayerSessions.Listener` 通知；大厅服务（组队、匹配、个人资料、商店、图片）只按玩家 id 工作，配置阶段的包由 `BLNetwork.anyToServer/anyToClient` 注册、按连接识别发送者 |
| 工匠 | 通用 `craft/*`（`Build`、`Craftable`、`CraftCatalog`、`Spray` + `SprayCatalog`），数据 `data/blockland/craft/attachments.json` + `sprays.json` + 各武器 `slots`，服务端 `server/craft/CraftService`，客户端 `client/craft/*`（逻辑 `CraftSession`；大厅分页 `CraftPanel`（经 `LobbyTab` 装进大厅，大厅不依赖工匠模块）；游戏内 `HeldCraftScreen` + `MountCallouts` / `OptionPicker` / `SkinCarousel`；`SprayEditor`）与 `client/spray/*` | 枪械与刀具共用：武器声明自己的槽位（挂点节点、默认、可选项、装上后隐藏的节点），配件只定义一次、任何武器都能用（瞄准镜、激光、枪管、枪托、挂件）；**喷漆**是改装方案的一部分：每处喷漆只存「喷漆 id + 哪一侧 + 侧视图中的 (u, v) + 尺寸 + 角度」，服务端不需要模型就能校验（id 存在且适用于该武器、坐标在 0..1、尺寸/角度在 `sprays.json` 的范围内、数量不超过上限），客户端按武器根节点的静止姿态把它投影到表面（`VIEWMODEL_SPEC.md` §29）；改装方案按玩家保存在**服务端**（后端玩家数据 `builds`，后端再检查一次格式），服务端校验每一项后保存，发放开局装备时自动套用；客户端只负责编辑与显示；**需要拥有的皮肤**（特殊皮肤默认如此，任何皮肤写 `"free": false` 即可）是库存物品（`craft/SkinKeys`：`skin:<武器>/<皮肤>`，共享皮肤另有 `skin:<皮肤>`，库存类型 `server/craft/SkinItems`），工匠只问「是否拥有这个键」：服务端拒绝保存未拥有的皮肤、权益过期后发放默认皮肤，客户端显示锁并允许试穿（`VIEWMODEL_SPEC.md` §30） |
| 设置 | 客户端 `client/settings/*`，准心 / 命中标记 `client/hud/Crosshair` + `HitMarker` | 语言与视角灵敏度是原版选项；瞄准灵敏度倍率、准心与命中标记样式只影响本机表现，保存在客户端（`config/blockland-settings.json`）；隐私（是否允许被邀请组队）保存在后端玩家数据，由服务端在邀请时执行 |
| 公告 | 后端 `announcement/*`（随 `/bootstrap` 同步），模组 `LobbyService` 转发，客户端 `ClientAnnouncements` + `client/screen/lobby/Announcement*` | 后台发布/编辑/删除；每名玩家的已读状态保存在后端（跟随账号），客户端标记已读后立即更新本地并通知服务器 |
| 枪械 · 数据 | `data/blockland/guns/guns.json` + `gun/GunCatalog` / `GunStats` | 弹药、弹匣、槽位、皮肤、枪械全部是数据（通用配件在 `craft/attachments.json`）；伤害/散布/后坐力/换弹时间/射程等有效数值（含配件的倍率）只在 `GunStats` 计算，客户端与服务端共用同一份 |
| 枪械 · 服务端 | `server/gun/GunService` | 唯一权威：校验每一枪（当前栏位、射速、余弹），用与客户端相同的散布种子做射线判定、爆头与距离衰减（消音器等配件的射程/伤害倍率），计时换弹并扣除背包弹药；双持武器的齐射（`shots` 2，只有 `dual.volley` 的武器可用，按 `volleyCost` 扣射速额度）与左右手（`hand`）都在这里校验；管式弹仓逐发装填由服务端按发计时、每发扣一颗弹药，开火可打断 |
| 枪械 · 客户端 | `client/gun/*`（输入、预测、HUD）、`client/gltf/*`（GLB 解析与动画采样）、`client/render/*`（GPU 渲染） | 客户端只做表现与预测；美术资源只通过 `tools/assets/VIEWMODEL_SPEC.md` 约定的节点名/动画名/材质名接入，换成美术制作的 GLB 无需改代码 |
| 第一人称 · 共用 | `client/viewmodel/*`（`ViewmodelRig`、`ViewmodelMotion`、`ViewmodelRenderer`） | 所有武器共用的部分：GLB 动画层（待机 / 单次动作 / 交叉淡化 / 疾跑循环）、相机节点、玩家皮肤手臂、程序化运动与独立视场角渲染；枪械（瞄准、后坐力、套筒、枪口火焰、激光）与刀具（命中回弹、镜头冲击）只在各自的视图模型里叠加 |
| 渲染 · 材质与皮肤 | `client/render/*`（`Textures` + `Mipmaps` 纹理组、`GpuModel` 逐材质解析、`DrawList`、`core/gun` PBR 着色器），`craft/SkinLibrary` + `data/blockland/craft/skins.json` | 材质是「数据 + 约定」：GLB 材质的 `extras` 指向 LabPBR 纹理组（颜色 / `_n` 法线 + AO / `_s` 光滑度、F0、自发光）并标明区域（枪身、枪管、弹匣、枪托、握把、护木、瞄具…）；皮肤按区域替换纹理组并可加着色器特效（`iridescent` 薄膜干涉、`flow` 流光、`galaxy` 星空、`circuit` 霓虹回路——在武器静止姿态空间里铺开，配件按挂点位置接续，图案跨枪身与配件无缝），共享皮肤按 `for` 自动加入每把对应武器，客户端与服务端读同一份数据、校验不变（`VIEWMODEL_SPEC.md` §20–§21）。**特殊皮肤**（§30）再多两样数据：`model`（遵守同一节点约定的另一个 GLB）与 `fx`（枪口火焰颜色/贴图/大小、曳光颜色/粗细、枪声）；服务端只用其中的枪声，其他玩家的客户端从射手手中物品读出皮肤来显示火焰与曳光 |
| 阴影捕获 | `client/render/ShadowPass`、`client/render/VanillaDraws` | 我的世界是 BlockLand 的引擎，不兼容 OptiFine / 光影包等其他渲染模组；原版实体渲染类型只用于太阳阴影图捕获第三人称武器 |
| 光学瞄具 | 客户端 `client/scope/*`：门面 `Optics`（所有瞄具：机械、红点/全息 `ReflexSights`、倍镜 `Scopes`），倍镜的画中画 `ScopePicture`、目镜 `ScopeEyepiece`、瞄准聚焦 `AimFocus`（所有瞄具）、可变倍率 `ScopeZoom`、呼吸与屏息 `ScopeSteady`、他人镜片反光 `ScopeGlints`、纯数学 `ScopeOptics`；服务端 `server/gun/GunService`（开镜计时）；数据为 `attachments.json` 中配件的 `scope` / `reflex` 对象 | 枪械模块只通过 `SightPose`（瞄具节点在本帧的位置）与门面交互，光学模块不认识枪。镜内画面是独立的第二次世界渲染（同一帧、同一相机、窄视场、按目镜像素决定分辨率，只在开镜时），与主画面隔离（裁剪视锥不绘制调试平面、独立的雾 uniform、不画名牌）；目镜着色器负责出瞳阴影、视差、分划辉光、色散、太阳眩光与鬼影、镜片污渍和按真实天空着色的反光。开镜后子弹沿本帧画出的瞄准线射出（准星即落点）；开镜状态由客户端上报（`C2SAim`），**服务端计时**，射击声称的瞄准程度不能超过开镜时间允许的值，并转发给附近玩家显示狙击镜反光（`S2CAim`）。倍率、晃动、屏息、虚化只影响本机表现。栓动节奏在 `client/gun/BoltCycle`（`VIEWMODEL_SPEC.md` §22–§23） |
| 武器输入 | `client/input/WeaponInput` | 左/右键的真实按下沿与共用的检视键（`I`）；枪械与刀具各自订阅，只在自己的武器在手时响应 |
| 移动 · 动作系统（滑铲 / 匍匐 / 飞扑） | 通用 `movement/action/*`（`SlideRules` / `ProneRules` / `DiveRules` 数据、`BodyActions` 两端视图）与 `combat/HitShapes`，服务端 `server/movement/ActionService`，客户端 `client/movement/*`（`ClientActions` 调度，`ClientSlide` / `ClientProne` / `ClientDive` 预测与镜头，`ActionPoses` 第三人称） | 是否允许是模式设置 `allowSlide` / `allowProne` / `allowDive`（类型可再收紧，如感染只允许人类）；客户端预测、服务端校验并下发姿态；枪械与刀具只通过 `BodyActions.eyePosition` / `HitShapes` 询问，不认识动作模块；武器的姿态由共用的 `ViewmodelMotion.BodyMotion`（`ProneLayer`）接入 |
| 刀具 · 数据 / 服务端 | `data/blockland/melee/knives.json` + `melee/*`，`server/melee/MeleeService` | 轻击 / 重击的伤害、距离、范围、出刀与命中时间、冷却、击退、背刺倍率、连击动画与切痕方向全部是数据；`MeleeTrace` 由服务端（伤害）与客户端（即时特效）共用。服务端唯一权威：校验栏位与冷却，在命中时刻重新判定并结算伤害，与枪械模块互不依赖（独立的 `MeleePacketListeners`） |
| 刀具 · 客户端 | `client/melee/*` | 输入（左键轻击可按住连斩、右键重击、检视）、连击交替、按键缓冲、命中时刻的本地特效与镜头冲击；共用 `client/hud/HitMarker` |
| 对局结算 | 模组 `server/game/MatchResult` + `MatchResultPublisher`，客户端 `client/result/*` | 游戏只用数据描述结果（胜负、原因、统计列、每名玩家一行）；发布器为每名玩家生成自己的结算面板（自己的胜负、高亮自己那一行）并下发，面板时长 = 结束阶段时长；按钮发 `C2SPostMatch`，服务端只在该玩家的对局处于结束阶段时接受，「再来一局」的模式取自服务端的对局记录、走与大厅相同的排队校验（队伍、装备布局） |
| 枪战感染 | 模组 `games/infection/*` + `data/blockland/infection/monsters.json` | 独立的游戏类型（不继承团队竞技场流程，只复用 `ArenaLoader` 载图与开局装备）；怪物的模型、血量、移速、技能全部是数据，技能按 `type` 由 `MonsterSkills` 实现（`effect` 自身效果、`projectile` 发射物）；左键伤害是模式设置、所有怪物一致；出生点角色读取地图的类型设置 `spawns`；怪物列表通过 `GameType.registryData()` 发布给后端；客户端只通过 `InfectionPackets` 收到要显示的内容，选择怪物与技能都由服务端校验 |
| 枪战爆破 | 模组 `games/bomb/*`（服务端）、`bomb/*`（物品 `blockland:c4`、已安放炸弹实体 `PlantedBomb`、`data/blockland/bomb/bomb.json`）、客户端 `client/bomb/*`（输入、第一人称、HUD、已安放炸弹的闪灯与滴答声）与 `client/bomb/fx/*`（爆炸特效着色器） | 继承团队竞技场流程（`TeamArenaGame` 的钩子：队名、淘汰判定、超时、结束原因）；谁携带炸药包、能否下包 / 拆包、进度与引信全部由服务端按 tick 计时，客户端只上报「按住了哪个键」（`BombPackets`），并只收到自己可以知道的状态（防守方不知道谁带包、包掉在哪）；包点读取地图的类型设置 `sites`；炸药包是类型提供的「角色物品」（`GameType.roleItems`），玩家可在装备布局里摆放，只有分配到的人才会拿到；爆炸不破坏方块 |
| 降落伞 | 通用门面 `parachute/Parachutes`（两端视图，如 `movement/action/BodyActions`）+ `parachute/*`（物品 `blockland:parachute`、`parachute.json`），服务端 `server/parachute/ParachuteService`，客户端 `client/parachute/*` | 穿在胸甲栏；空中按跳跃键开 / 收伞，客户端预测、服务端校验并同步给周围玩家；游戏（如大逃杀）只通过门面 `equip` / `deploy` / `isOpen` 使用 |
| 开放世界 | 模组 `games/world/*`、维度 `data/blockland/dimension/world.json` | 「随时进入」类型（`GameType.dropIn` + `GameInstance.addPlayers`，匹配直接加入该模式唯一运行的实例）；玩家状态按模式保存在服务端（`<存档>/blockland/world/<模式>/<uuid>.dat`），开局装备只在第一次进入时发放 |
| 大逃杀 | 模组 `games/battleroyale/*`、共享 `battleroyale/*`（飞机实体 `BrPlane`，航线为同步数据）、客户端 `client/battleroyale/*` | 开场环绕岛屿的镜头 → 飞机航线（按跳跃键跳下）→ 降落伞（低空自动打开）→ 地面物资（地图类型设置 `lootSpots` 或随机地表点，模式的 `loot` 表）→ 缩圈 → 最后存活者获胜；全部由服务端计时与判定 |
| 观察者画面 | 模组 `server/spectate/SpectateService`，客户端 `client/spectate/*`，游戏只提供 `GameInstance` 的 `spectateTargets` / `respawnTicks` / `spectateBounds` | 对局中处于旁观模式的参与者自动进入观察：默认观察击杀者（原版旁观镜头），攻击 / 使用键切换玩家，交换副手键切换第一 / 第三人称（客户端环绕镜头，滚轮远近），跳跃键进入自由视角（不能离开对局范围）；会复活的玩家观察到复活为止，否则到对局结束或模式设置 `spectateSeconds` 后回大厅；`spectate` / `spectateFreeCam` 是模式设置；HUD 显示被观察者的名片、段位、排名与游玩时长 |

| 生物与效果 | 模组 `entity/*`（`SlimeLicker`、`CreeperZombie`、`GhastLord`、`SlimeShot`、`SkillFireball`、`EffectPayload`）、`effect/*`（`BLEffects`、`ActionLocks`），客户端 `client/creature/*`、`client/effect/ClientActionLock` | 与游戏无关的内容：粘液舔舐者实体（改造的僵尸模型，供变身使用）、带效果的发射物、「粘液缠身」效果。`ActionLocks.isLocked` 是唯一的判断：枪械、刀具服务端拒绝被锁玩家的开火/攻击，原版攻击、使用物品、方块/实体交互同样取消；客户端据此即时屏蔽左右键并铺上粘液画面 |

## 功能

- **游戏大厅**（进服后强制显示，对局结束后自动回到这里）：**大厅里不加载任何世界**——玩家停在连接的配置阶段，客户端没有世界、服务端没有玩家实体，直到匹配成功、地图准备好时才直接载入对局地图，对局结束再退回大厅。大厅界面不能关闭（没有世界可回），顶栏右侧有「设置」「退出服务器」（OP 另有「进入世界」，在世界中按 `M` 或 `/bl lobby` 回到大厅）。
  - 标签页：**开始游戏** / **工匠** / **公告**（显示未读数）/ **商店**（模拟支付）。
  - 开始游戏：左侧「选择游戏模式」先显示分组卡片（封面、标题、介绍、模式数）与未分组的模式，点开分组后只显示该组模式（「‹ 全部模式」或 `ESC` 返回）；中间为玩家人物模型（固定角度、呼吸浮动）；右下角为所选模式、**地图选择**与「开始匹配 / 取消匹配」。
  - **地图选择**：选中模式后可选「随机地图」或该模式地图池中的任一张（左右箭头切换，点名称打开列表，有封面时显示缩略图），每个模式分别记住；排队时随请求发送，服务端校验地图属于该模式。想要不同地图的玩家不会被匹配到一起，选随机的玩家可与任何人匹配；同一局里第一个指定地图的队伍决定地图。
  - **公告提醒**：右上角（组队栏下方）显示**未读**公告，最多同时两条，带发布时间与内容摘要，按发布时间从旧到新；点「已阅」后下一条才补上来，点卡片在「公告」页打开全文。「公告」页列出全部公告（置顶在前，其余从新到旧），打开即标记已读，可「全部标为已读」。已读状态保存在服务器（换电脑也保留）。
  - 全部动效使用模组自带动画系统：开场依次入场、卡片弹簧悬停/按压、分组切换滑动 + 交错入场、按钮颜色过渡与匹配中扫光、计时跳动。
- **设置**（大厅顶栏「设置」；对局中按 `O` 或在暂停菜单右上角点「BlockLand 设置」）：
  - 通用：界面语言 简体中文 / English（切换后重新加载资源，大厅与游戏内全部文字随之切换）。
  - **画质**：BlockLand 渲染管线总开关与预设（低 / 中 / 高 / 极高，改动任一项即为「自定义」）；分辨率与抗锯齿（超分辨率 关 / BlockLand 超分 / DLSS 超分辨率 / DLAA，渲染质量 原生 / 质量 / 平衡 / 性能 / 超高性能（DLSS 为 质量 / 平衡 / 性能 / 超高性能），原生分辨率时抗锯齿 关 / FXAA / TAA，锐化；选 DLSS / DLAA 时还有 DLSS 模型预设 默认 / J / K / L / M 与 DLSS 锐化；DLSS 帧生成 关 / 2×–6×（3× 起为多帧生成）与 NVIDIA Reflex 开 / 开 + 加速；并说明光线重建为何不适用）；光影（世界光照开关——关闭设置时重新加载资源，阴影质量与距离、柔和度、阳光强度、动态光源、手持光源、自发光、水面反射与折射（折射需要原版「极佳！」画质，可一键切换）、武器受世界光照）；屏幕空间效果（环境光遮蔽、体积光）；镜头与色彩（泛光、自动曝光与曝光补偿、色调映射 原版保真 / 电影 / ACES、**世界动态模糊**与**手臂与武器动态模糊**、暗角、色差、胶片颗粒、饱和度、对比度、色温）；状态区实时显示管线是否运行、内部 → 输出分辨率、当前抗锯齿 / 超分、DLSS 是否可用及原因、世界光照状态与显卡。改动即时生效，保存在本机。
  - 枪械：视角灵敏度；**按倍率分档的瞄准灵敏度**——1×（机瞄 / 红点 / 全息）与 2×、3×、4×、6×、8×、10×+ 瞄准镜各有自己的倍数，叠加在倍镜按倍率自动降低的转动之上（全部 1.00 即画面移动速度与裸眼一致），介于两档之间的倍率（如狙击镜的 9×、切换倍率时的过渡）在相邻两档之间按对数插值；旧的单一倍镜灵敏度会自动迁移到各档；**准心**（形状：十字 / 十字+中心点 / T 型 / 圆点 / 圆环，颜色、不透明度、线长、粗细、间距、描边、是否随扩散张开）；**命中标记**（形状：斜叉 / 十字 / 圆环，命中 / 爆头 / 击杀三种颜色、大小、粗细、持续时间）；**瞄准镜**（镜内画面质量 关 / 低 / 中 / 高、瞄准时聚焦、开镜时镜外变暗）。颜色可选预设或用 RGB 滑块自定义，右侧实时预览准心与轮流播放的命中标记。保存在本机。
  - 隐私：是否允许其他玩家邀请我组队（保存在服务器，关闭后邀请会被服务器拒绝）。
- **公告（后台）**：「公告」页可发布多条公告（标题、多行内容、置顶），编辑、删除；游戏服务器在下次同步（默认 30 秒内）后推送给大厅中的玩家。
- **小游戏管理**：添加模式（Title、游戏类型、介绍、封面（16:9，自动缩放到 512×288）、启用、可选存活时间），首次启动自动生成 **空岛战争 1v1 / 4v4** 与 **ClassPVP**（含示例封面）。
- **模式分组**（后台「小游戏管理」页内，模式按分组列出）：封面、Title、介绍、排序、启用以及有序的小游戏列表；编辑模式时可直接选择「所属分组」。示例分组「空岛战争」（1v1、4v4）、「PVP 竞技」（ClassPVP）与「枪战感染」。
- **组队**：大厅右上角显示队伍成员头像（★ 队长，颜色表示大厅 / 匹配中 / 对局中），点「+」输入玩家名称邀请（被邀请者在设置中关闭了组队邀请时会提示对方不接受）；被邀请者在大厅中看到邀请卡片（接受 / 拒绝，60 秒有效）。只有队长可以开始匹配，整队一起排队并分在同一队伍；队员可取消匹配；成员变化会自动取消当前匹配。队伍人数超过模式每队人数时无法匹配。上限由配置 `party.maxSize`（默认 4）决定。
- **无世界大厅**：大厅期间客户端不加载世界、服务端不创建玩家实体，主世界不加载区块；进入对局时客户端直接载入对局地图。
- **限时模式**：小游戏可设置「限时开放」截止时间，到期后自动关闭（正在排队的玩家会被移出队列，进行中的对局不受影响）。大厅中限时模式带金色边框与「限时 · 剩余 N 天」标签（最后两天闪烁），分组卡片显示「限时」，右下角详情显示截止时间。
- **转让队长**：队长把鼠标移到队员头像上，点左上角的 ★ 即可转让；正在进行的匹配不会被取消。
- **枪械系统**（**P9 手枪**、**P9A 冲锋手枪**、**USP 手枪**、**双持 USP**、**汤姆逊冲锋枪**、**AK-47 突击步枪**、**KS-3 霰弹枪**、**AWP 狙击步枪**）
  - 操作：左键射击，右键瞄准（ADS），`R` 换弹，`I` 检视，`G` 打开工匠，`B` 切换射击模式（均可在按键设置中修改）。
  - 射击模式：每把枪声明支持的模式（`guns.json` 的 `fireModes`，第一个为默认）。**P9 手枪**仅半自动（每按一次左键一发，按住挖方块也不会连发）；**P9A 冲锋手枪**默认全自动（约 1050 发/分），可按 `B` 切换为半自动。
  - 弹药：手枪 / 步枪 / 冲锋枪 / 霰弹枪 / 狙击枪弹药（物品，每种有自己的伤害、爆头倍率与适配弹匣）；弹匣：标准 / 扩容（适配枪械、容量、换弹与开镜速度）。换弹从背包扣除对应弹药，创造模式不消耗。
  - 每把枪有自己的名称、GLB 模型、皮肤、检视与换弹动画、射速、后坐力、腰射/瞄准精度、距离衰减；全部在 `guns.json` 中配置。
  - 爆头：命中头部（眼睛略下方以上）伤害乘以弹药的爆头倍率；命中/爆头/击杀有不同的命中标记与音效。

- **快速PVP（FASTPVP）**：自定义开局装备、是否允许破坏/放置方块（服务端以 Forge 破坏事件的 DENY 结果拒绝；两者都不允许时玩家处于冒险模式，客户端连挖掘都不会开始）、可选限时、每队人数 × 队伍数、自定义地图；淘汰后不掉落装备。示例模式 **ClassPVP**（1v1，铁套 + 铁剑，示例竞技场地图）。
- **用户（后台）**：玩家列表、在线状态、总在线时间、最后在线；封禁 / 禁言（原因 + 时长或永久，在线玩家 15 秒内被踢出或禁止聊天）；手动授予 / 收回权益。
- **商店（后台）**：商品包含名称、图片（自动转 PNG ≤256px，游戏内同步显示）、介绍、价格、分类、权益标识与有效期；订单列表。首个商品 **优先匹配排队**（¥9.90 / 30 天，授予 `PRIORITY_QUEUE`，重复购买顺延）；示例皮肤商品（分类「皮肤」，永久）：双持 USP「地狱犬」¥38、KS-3「龙息」/ 汤姆逊「芝加哥」/ AWP「雷霆」各 ¥28，权益标识即皮肤的库存物品键（如 `skin:usp_dual/cerberus`，在「权益标识」下拉中可选）。
- **反作弊（后台）**：「反作弊」页的案件列表（待复核优先）与详情（各检测统计、证据时间线、处罚与备注；封禁 / 确认误判 / 不予处理 / 继续观察），设置页编辑全局开关、自动封禁、提醒、证据保留与预设（严格 / 标准 / 宽松 / 仅记录，可按检测调整）；每个模式在「小游戏管理」里选预设并可按检测覆盖；用户页标出有进行中案件的玩家（契约见 `tools/anticheat/ANTICHEAT_SPEC.md`）。
- **优先匹配排队**：拥有 `PRIORITY_QUEUE` 权益的玩家在所有队列中排在最前面（同类按加入顺序）；大厅匹配面板显示「★ 优先匹配」，OP 可用 `/bl queue <模式ID>` 查看队列顺序。
- **空岛战争**
  - 导入地图：上传 `.nbt` / `.schem`，自动识别尺寸、所有箱子/木桶坐标，可选「出生点标记方块」自动生成出生岛（相邻标记归为同一队）。
  - 匹配人数：每队人数 × 每局队伍数（预设 1v1 / 2v2 / 4v4 / 8 人混战等）。
  - 物资：物资表中每个物品可设置数量范围与出现概率，支持 `/give` 组件语法（附魔等）；每箱最少/最多物品数；后台可「模拟开箱」。
  - 按坐标为每个箱子单独指定物资表（俯视图点选 + 批量设置），未指定的使用地图默认物资表；地图中未登记的箱子也会使用默认物资表。
  - 对局流程：加载并分批粘贴地图到独立虚空维度 `blockland:arena` → 玻璃笼倒计时 → 开战（队友无伤、虚空判定、击杀播报、可选箱子刷新）→ 最后存活队伍获胜 / 到达存活时间按存活人数判定 → 结算后返回大厅并清理场地。

## 运行

### 1. 后端 + 管理后台

```bash
cd server/web && npm install && npm run build
```

```bash
cd server/backend && mvn package
```

```bash
cd server/backend && java -jar target/blockland-backend-0.1.0.jar
```

打开 <http://localhost:8080>，使用 `application.yml` 中的 `blockland.admin-token` 登录。**上线前请修改 `admin-token` 与 `server-token`。** 数据保存在 `server/backend/data/`。

前端开发：后端运行时执行 `npm run dev`（<http://localhost:5173>，`/api` 自动代理到 8080）。

### 2. 模组

本机默认 `JAVA_HOME` 是 JDK 8，Gradle 9 需要 17+；`build.ps1` 会自动改用 JDK 26，并绕过 JDK 26 在本机 Windows 上的 NIO 管道问题（`Unable to establish loopback connection`）。编译用的 Java 21 工具链由 Gradle 自动下载。

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 build
```

产物（`mod/build/libs/`）：

- `blockland-0.1.0-client.jar`：发给玩家。不含服务端的一半（`server/`、`games/`、反作弊与远景地形的 mixin、只有服务端读的数据如反作弊阈值、感染怪物），反编译看不到服务端逻辑；用它自己开单人 / 局域网世界时没有 BlockLand 的玩法服务。误把它装到专用服务端会在启动时直接报错。
- `blockland-0.1.0-server.jar`：装在专用服务端。不含客户端的一半（`client/`、渲染与界面的 mixin、贴图 / 模型 / 着色器 / 声音 / 字体与内置资源包，只保留语言文件），约 2 MB。误把它装到客户端会在启动时直接报错。

`build` / `assemble` 会顺带跑 `checkClientJar` 与 `checkServerJar`：任一 jar 里只要有类引用了被剥离的类或数据（导入、反射字符串、mixin 目标都算），构建就失败。

开发测试（`mod/run-server` 已配置为离线模式 + 超平坦 + 仅本机 RCON）：

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 runServer
```

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 runClient -PjoinServer=localhost:25565 -PdevName=Steve
```

**服务器地址**：默认 `localhost:25565`（`server-ip` 为空 = 监听所有网卡，局域网内其他电脑用本机 IP:25565）。开发服务器是离线模式，同时开两个客户端只需名字不同，第二个客户端用独立的游戏目录：

```bash
cd mod && powershell -ExecutionPolicy Bypass -File build.ps1 runClient -PjoinServer=localhost:25565 -PdevName=Alex -PclientDir=run2
```

`build.ps1` 会把系统的 `HTTPS_PROXY`（如本机 Clash `127.0.0.1:7890`）转换为 Java 代理参数，否则 Mojang 资源下载会超时。

服务器配置 `config/blockland-common.toml`：

```toml
[backend]
url = "http://127.0.0.1:8080"
serverToken = "change-me-server"
syncIntervalSeconds = 30
```

开发服务器的 `ops.json` 已将开发客户端玩家 **Steve** 设为 4 级 OP（离线模式 UUID），用 `-PdevName=Steve` 启动客户端即可直接使用 OP 命令。

### 开发测试驱动

开发客户端可加 `-Pautomation=<目录>` 启动（例如 `.\build.ps1 runClient -PdevName=Steve -Pautomation=C:/tmp/auto`），
客户端会读取 `<目录>/<玩家名>.txt` 中的测试指令（按键、选栏位、执行命令、瞄准某玩家、截图等，见
`client/dev/DevAutomation.java`），结果追加到 `<目录>/<玩家名>.log`。不加该参数时完全不启用，不影响正常游戏。

### 武器美术资源

`tools/assets/` 下的程序化生成器（`python -I tools/assets/build_all.py`）生成 P9、USP、双持 USP、AK-47、AWP、蝴蝶刀与匕首的 GLB、通用配件（含二倍镜、狙击镜与分划贴图、三种枪托）、手臂、图标、低模、特效与损伤贴图、喷漆贴图、音效；汤姆逊、KS-3 与双持 USP 的「地狱犬」皮肤模型由转换脚本从 CC-BY-4.0 模型改造而来（作者与来源见 `tools/assets/CREDITS.md`，不附带原模型贴图；转换后的零件缓存在仓库里，没有原文件也能重新生成）。之后的武器各自用一组模块接入（`pbr_sets_*`、`pbr_models_*`、`build_*`、`check_*`，见各钩子元组），可以并行开发；`pbr_textures.py` 生成 LabPBR 纹理组，`pbr_apply.py` 把纹理组、区域与烘焙的顶点 AO 写进每个 GLB（`build_all.py` 会自动执行，单独重新生成 AWP / 瞄准镜后需再运行一次 `pbr_apply.py`），`pbr_check.py` 检查纹理组与皮肤数据，`check_glb.py` 还会把每个模型从 14 个方向不剔除背面地渲染一遍（`check_orient.py`），露出背面的零件（法线朝内、看进去像空心）、绕序不一致的面和不该透明的材质都会报错；
美术制作的模型只要遵守 `tools/assets/VIEWMODEL_SPEC.md`（节点名、相机空间、动画名与事件、材质名），放进资源包即可替换（F3+T 重新加载）。

### 游戏内命令

| 命令 | 说明 |
|---|---|
| `M` / `/bl lobby` | 在世界中（OP 进入世界后）返回大厅；大厅本身进服即显示 |
| `/bl join <模式ID>` | 用命令加入匹配队列（等同于大厅里的「开始匹配」，使用默认装备布局） |
| `/bl queue <模式ID>` (OP) | 查看队列顺序（★ = 优先匹配） |
| `/bl leave` | 离开对局（阵亡后观战时也可用）并返回大厅 |
| `/bl reload` (OP) | 立即同步后端配置 |
| `/bl status` / `/bl games` / `/bl stopall` (OP) | 状态、进行中对局、中止全部对局 |
| `/bl start <模式ID>` (OP) | 用队列中的玩家立即开局（可单人测试） |
| `/bl ac status [玩家]` / `alerts` / `exempt <玩家> <秒>` / `reset <玩家>` / `stats` (OP) | 反作弊：玩家的预设、延迟、补偿窗口、置信度与各检测 VL；开关自己的提醒；临时豁免移动检测；清空违规；反作弊每 tick 的耗时 |
| `/bl map preview <地图ID>` / `/bl map here` / `/bl map close` (OP) | 预览地图并查询脚下/准星方块的**相对坐标**，用于填写出生点与箱子 |

## 坐标约定

地图中所有坐标都相对于结构/schematic 的最小角 `(0,0,0)`。出生点坐标是玩家**脚下所在的方块**；朝向 yaw 与 Minecraft 相同（0 = 南，90 = 西）。队伍按出生岛列表均匀分配，例如 8 个岛的 1v1 使用第 1 和第 5 个岛。
